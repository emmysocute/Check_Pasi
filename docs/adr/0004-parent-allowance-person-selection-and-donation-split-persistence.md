# ADR 0004: การปรับปรุง UI ลดหย่อนบิดามารดาตามรายบุคคล, การแยกจัดเก็บเงินบริจาค 2 เท่า และการรวม Utility ตัวเลข

## สถานะ (Status)
อนุมัติแล้ว (Accepted)

## บริบท (Context)
หลังจากการดำเนินการรอบ Code Review และการปรึกษาร่วมกับผู้ใช้เกี่ยวกับเกณฑ์ลดหย่อนภาษีตามประมวลรัษฎากร ได้ข้อสรุป 3 ประเด็นสำคัญที่ต้องปรับปรุง:

1. **เกณฑ์ลดหย่อนบิดามารดา (ม.47(1)(ช)):**
   - กฎหมายสรรพากรกำหนดค่าลดหย่อนอุปการะเลี้ยงดูบิดามารดาเป็น **อัตราคงที่คนละ 30,000 บาท** (ไม่ใช่กรอกตามค่าใช้จ่ายจริง) ได้สูงสุดไม่เกิน 4 คน (บิดา-มารดาตนเอง 2 คน และบิดา-มารดาคู่สมรส 2 คนในกรณีคู่สมรสไม่มีเงินได้)
   - ช่องกรอกข้อมูลเดิมเป็นช่องตัวเลขเงินบาทอิสระ ทำให้ผู้ใช้อาจเข้าใจผิดกรอกจำนวนเงินที่ไม่ตรงกับกฎหมาย (เช่น 15,000 หรือ 50,000)
2. **การกู้คืนข้อมูลเงินบริจาค (Donation Persistence Loss):**
   - สิทธิลดหย่อนเงินบริจาคแบ่งเป็น 2 อัตรา คือ สิทธิ 2 เท่า (การศึกษา/กีฬา/รพ.รัฐ) และสิทธิ 1 เท่า (ทั่วไป)
   - ฐานข้อมูลเดิมเก็บเพียงคอลัมน์รวม `donation` ทำให้เมื่อผู้ใช้ล็อกอินและระบบดึงประวัติล่าสุด (`fetchLatest`) ยอดบริจาค 2 เท่าจะถูกดึงกลับมาเป็นยอดทั่วไปทั้งหมด
3. **ความซ้ำซ้อนของโค้ด (Duplicated Code Smell):**
   - ฟังก์ชันดักคีย์ตัวอักษรที่ไม่พึงประสงค์ (`blockInvalidChars`) และฟังก์ชันตรวจสอบ/จำกัดค่าตัวเลข (`sanitizeNumericInput`) ถูกเขียนซ้ำในหลายคอมโพเนนต์

## การตัดสินใจ (Decision)

### 1. ปรับปรุง UI ลดหย่อนบิดามารดาเป็น Checkbox 4 รายการ (Parental Checkbox Selection)
- ปรับเปลี่ยนช่องกรอกเงินบาทเดิมในหมวดบิดามารดา ให้เป็น Checkbox เลือกรายบุคคล 4 ท่าน:
  - `[✓] บิดาของผู้มีเงินได้ (30,000 บาท)`
  - `[✓] มารดาของผู้มีเงินได้ (30,000 บาท)`
  - `[✓] บิดาของคู่สมรส (30,000 บาท)` *(เงื่อนไข: คู่สมรสไม่มีเงินได้)*
  - `[✓] มารดาของคู่สมรส (30,000 บาท)` *(เงื่อนไข: คู่สมรสไม่มีเงินได้)*
- ระบบจะคำนวณยอดเงินรวมให้อัตโนมัติ ($30,000 \times \text{จำนวนคนที่เลือก}$ สูงสุด 120,000 บาท)

### 2. แยกคอลัมน์จัดเก็บเงินบริจาคในฐานข้อมูล (Dual-Rate Donation Persistence)
- เพิ่มคอลัมน์ใหม่ในตาราง `tax_records` ผ่าน Non-destructive Auto-migration:
  - `donation_education DECIMAL(12,2) DEFAULT 0`
  - `donation_general DECIMAL(12,2) DEFAULT 0`
- คอลัมน์ `donation` เดิมยังคงเก็บยอดรวมลดหย่อนจริงหลัง Cap 10% เพื่อความเข้ากันได้ย้อนหลัง (Backward Compatibility)
- ปรับปรุง API `POST /calculate` และ `GET /history` ให้บันทึกและกู้คืนค่าทั้งสองช่องได้อย่างแม่นยำ

### 3. รวมโมดูลตรวจสอบและรับค่าตัวเลข (Shared Input Sanitization)
- สร้าง Utility กลางที่ [`src/utils/numberInput.js`](file:///c:/kmitl/PEE3/Cloude/project/Check_Pasi/src/utils/numberInput.js) รวบรวม:
  - `blockInvalidChars(e)`: ป้องกันการกด `-`, `+`, `e`, `E`
  - `sanitizeNumericInput(val, max)`: แปลงและจำกัดช่วงตัวเลขให้อยู่ในขอบเขตที่ปลอดภัย ($\ge 0$)
- นำไปใช้ร่วมกันใน [`IncomeSection.jsx`](file:///c:/kmitl/PEE3/Cloude/project/Check_Pasi/src/components/IncomeSection.jsx) และ [`DeductionSection.jsx`](file:///c:/kmitl/PEE3/Cloude/project/Check_Pasi/src/components/DeductionSection.jsx)

## ผลลัพธ์ (Consequences)
- ผู้ใช้ได้รับการแนะนำสิทธิลดหย่อนบิดามารดาที่ตรงตามข้อกำหนดกฎหมายสรรพากร ป้องกันการกรอกตัวเลขผิดพลาด
- ข้อมูลประวัติการคำนวณบริจาค 2 เท่าไม่สูญหายเมื่อกู้คืนข้อมูล
- ลด Code duplication ลง ทำให้โค้ดสะอาดและดูแลรักษาง่ายขึ้นตามหลัก Clean Code
