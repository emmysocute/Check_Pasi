# ADR 0002: การปรับปรุงระบบ Responsive Layout และ Mobile Navigation

## สถานะ (Status)
อนุมัติแล้ว (Accepted)

## บริบท (Context)
ระบบ Check Pasi (TaxMe) เดิมถูกออกแบบโดยเน้นการแสดงผลบนหน้าจอ Desktop เป็นหลัก โดยเมื่อเปิดบนหน้าจอขนาดเล็กลง เช่น แท็บเล็ตและสมาร์ตโฟน (< 768px) จะพบปัญหาดังนี้:
1. แถบเมนูนำทาง (`.sidebar`) ถูกซ่อนด้วย `display: none` โดยไม่มีเมนูทางเลือก ทำให้ผู้ใช้งานบนมือถือไม่สามารถเปลี่ยนหน้าหรือใช้งานเมนูหลักได้
2. แถบส่วนหัว (`Topbar`) แสดงผลล้นหน้าจอ มีการซ้อนทับกันระหว่างชื่อผู้ใช้, สโลแกน และปุ่มออกจากระบบ
3. หน้าสรุปข้อมูลสถิติ (`HomePage`) มีการใช้สไตล์แบบ Inline ระบุ 2 คอลัมน์แบบตายตัว ทำให้การ์ดและกราฟวงกลม Recharts ถูกบีบอัดจนเสียสัดส่วนบนหน้าจอมือถือ
4. ตารางประวัติการคำนวณภาษี (`HistoryPage`) ไม่มีระบบรองรับหน้าจอเล็ก ข้อความและปุ่มคำสั่งตกขอบ
5. หน้าคำนวณภาษี (`TaxCalculatorPage`) มีความยาวแบบฟอร์มมาก ทำให้การวางผลลัพธ์ต่อท้ายต้องเลื่อนหน้าจอลงไปลึก

## การตัดสินใจ (Decision)

### 1. ระบบนำทางบนมือถือ (Mobile Navigation Drawer)
- ติดตั้งปุ่ม **Hamburger Icon** บนแถบส่วนหัว (`Topbar`) แสดงเฉพาะหน้าจอที่ขนาด `< 768px`
- ปรับโครงสร้างแถบเมนู (`Sidebar`) ให้ทำหน้าที่เป็น **Off-Canvas Drawer** บนมือถือ:
  - ค่าเริ่มต้นถูกเลื่อนซ่อนไว้ทางซ้าย (`transform: translateX(-100%)`)
  - เมื่อเปิด จะเลื่อนสไลด์เข้ามาอย่างนุ่มนวล (`transform: translateX(0)`)
  - มีฉากหลังมืดโปร่งแสง (**Backdrop Overlay**) ที่แตะเพื่อปิดได้ และปิดเมนูอัตโนมัติเมื่อมีการคลิกเปลี่ยนเส้นทาง (Route Change)

### 2. แถบส่วนหัวและข้อมูลผู้ใช้ (Responsive Topbar)
- ซ่อนข้อความสโลแกนยาวบนหน้าจอมือถือ คงไว้เฉพาะโลโก้และชื่อ TaxMe
- ยุบการแสดงชื่อผู้ใช้ให้กะทัดรัด (แสดงเฉพาะไอคอน Avatar หรือชื่อสั้น) และปรับขนาดปุ่มให้พอดีกับหน้าจอมือถือ

### 3. เลย์เอาต์แดชบอร์ดหน้าหลัก (HomePage Dashboard Grid)
- เปลี่ยนจากการระบุ Inline Grid มาใช้คลาส `.dashboard-grid` ใน `src/index.css`
- บนหน้าจอ Desktop/Tablet กว้าง: แสดง 2 คอลัมน์สมมาตร
- บนหน้าจอมือถือ (`< 768px`): ยุบเป็น 1 คอลัมน์แบบเรียงเดี่ยว (Stack) พร้อมจัดขนาดกราฟวงกลมให้พอดีหน้าจอ

### 4. ผลลัพธ์ภาษีและปุ่มลัด (Tax Calculator & Floating Quick-Jump)
- บนหน้าจอมือถือ: วางการ์ดผลลัพธ์ (`ResultPanel`) ต่อท้ายแบบฟอร์มอย่างเป็นระเบียบ
- เพิ่มปุ่มลอยหรือแถบลัด **Floating Quick-Jump Button** ด้านล่างของหน้าจอ เมื่อเริ่มเลื่อนดูแบบฟอร์ม เพื่อให้ผู้ใช้สามารถแตะแล้วเลื่อนลงมาดูสรุปยอดภาษีได้ทันทีโดยไม่ต้องปัดหน้าจอเอง

### 5. ประวัติการคำนวณภาษีแบบ Adaptive Card View (History Page)
- บนหน้าจอ Desktop (≥ 768px): แสดงผลในรูปแบบตารางข้อมูลที่มีคอลัมน์ครบถ้วน พร้อมคอนเทนเนอร์รองรับการเลื่อนกรณีหน้าจอกลาง
- บนหน้าจอมือถือ (< 768px): สลับไปแสดงผลเป็น **Card View** โดยแต่ละรายการคำนวณจะถูกนำเสนอเป็นการ์ด 1 ใบ แสดงข้อมูลวันที่, รายได้, ค่าลดหย่อน, ยอดภาษีสุทธิเด่นชัด และปุ่มลบรายการที่แตะง่าย

## ผลลัพธ์ (Consequences)
- ระบบสามารถใช้งานได้อย่างสมบูรณ์และสวยงามตั้งแต่หน้าจอมือถือขนาดเล็ก (320px) จนถึงหน้าจอคอมพิวเตอร์ขนาดใหญ่
- ผู้ใช้งานมือถือสามารถเข้าถึงทุกฟีเจอร์ได้ครบถ้วนโดยไม่มีเมนูสูญหาย
- ประสบการณ์การใช้งาน (UX) ไหลลื่น ชัดเจน และเป็นไปตามมาตรฐานการออกแบบเว็บสมัยใหม่
